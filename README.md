# כלי אוטומציה KBB / DCS — גרסת אתר עצמאית

אתר פנימי קטן (Flask) שמריץ מקומית שלושה מהתהליכים שהיו עד היום סקילים
ב-Claude, בלי צורך ב-AI בזמן ריצה: כל העיבוד (חילוץ מ-PDF, בניית Excel,
ייצוא ל-PDF) קורה בקוד רגיל על המחשב שמריץ את השרת. עובד יכול להשתמש בזה
דרך הדפדפן בלי לדעת שיש כאן קוד בכלל.

## מה יש כאן

1. **רשימות SMS שבועיות** (`/weekly-sms`) — מלא ומוכן לשימוש. מעלים את
   דוח ה-Operational Business, מקבלים קובץ SMS (5 גיליונות) + קובץ App2U.
   נבדק מקצה לקצה על נתוני דוגמה — תבניות ה-SMS, סדר העדיפויות בטלפון,
   חלוקת 0-6/7+ ימים, הכל בדיוק לפי מה שסוכם.

2. **איחוד תעודות משלוח (Packing List)** (`/packing-list`) — מלא, נבדק
   מקצה לקצה כולל בדיקת שורות/כמויות, טבלת פירוט לפי משלוח, טבלת פריטים
   מאוחדת, ותיקון כל התקלות הידועות (עמודות שנחתכות ב-PDF, טקסט שנחתך
   בכותרות). **הפרסינג של קבצי ה-PDF כן נבדק** מול קבצים סינתטיים שבנוי
   בדיוק לפי הפורמט המתועד (rows בפורמט `PartNumber HAL... PO... Country`)
   — אבל לא מול קובץ PDF אמיתי שלכם. מומלץ להריץ פעם אחת על משלוח אמיתי
   ולהשוות ידנית לפני שסומכים על זה במאה אחוז.

3. **חשבונית משלוח KBB** (`/invoice`) — עובד מקצה לקצה, אבל עם הסתייגות
   אחת משמעותית: **חסר לי הקובץ האמיתי של תבנית ה-Excel** (`COMMERCIAL
   INVOICE MANUAL RMA KBB.xlsx`) וגם **אף חשבונית Proforma אמיתית** לבדוק
   מולה. ראו "מה חייבים לעשות לפני שימוש אמיתי" למטה — זה לא אופציונלי.

## דרישות התקנה

- Python 3.10 ומעלה.
- **LibreOffice** מותקן על המחשב (משמש להמרות xlsx→PDF, xlsx→xls ישן,
  ולחישוב נוסחאות בפועל). ב-Mac: `brew install --cask libreoffice`.
  ב-Windows/Linux: מהאתר הרשמי של LibreOffice / מנהל החבילות הרגיל.
  אחרי ההתקנה ודאו שהפקודה `soffice` נגישה מה-Terminal (אם לא, אפשר
  להוסיף את התיקייה שלה ל-PATH).

## התקנה והרצה

```bash
cd kbb-web-tools
python3 -m venv venv
source venv/bin/activate        # ב-Windows: venv\Scripts\activate
pip install -r requirements.txt
python3 app.py
```

השרת עולה על `http://localhost:5000`. כדי שגם עובד ממחשב אחר באותה
רשת משרדית יוכל להיכנס — לוקחים את כתובת ה-IP המקומית של המחשב שמריץ
את השרת (למשל `192.168.1.23`) והעובד נכנס ל-`http://192.168.1.23:5000`.
אם רוצים שהאתר ירוץ קבוע ברקע (לא רק כשהטרמינל פתוח), אפשר להריץ אותו
כשירות (systemd ב-Linux, launchd ב-Mac, NSSM/Task Scheduler ב-Windows) —
אשמח לעזור להגדיר את זה בנפרד אם תרצו.

**הערת אבטחה:** זה כלי לרשת פנימית/משרדית בלבד. אין בו התחברות/סיסמה,
ואין להעלות אותו לאינטרנט הפתוח כמו שהוא.

## מה חייבים לעשות לפני שימוש אמיתי בכלי החשבונית

1. **תבנית ה-Excel האמיתית**: העתיקו את `COMMERCIAL INVOICE MANUAL RMA
   KBB.xlsx` האמיתי שלכם (מה-Project ב-Claude) לנתיב:
   `assets/kbb_invoice_template.xlsx`
   הקוד מניח את פריסת התאים המתועדת (H3/H5/H15/H22/H23, טבלת פריטים
   משורה 31, 20 שורות מוכנות 32–51, סכום ב-G52, DIMS ב-D53, הערת
   הצהרה ממוזגת מתחת). אם התבנית האמיתית שלכם תואמת לזה (וזה מה
   שהסקיל המקורי היה עובד מולו) — זה אמור לעבוד ישר. אם משהו שונה,
   תשלחו לי את הקובץ (אפשר עם נתונים מזויפים/מוסתרים) ואכייל.

2. **חילוץ הנתונים מחשבוניות ה-Proforma**: זה החלק שממש כדאי להיזהר
   ממנו. הסקיל המקורי היה קורא כל PDF בעזרת היכולת ה"חזותית" של Claude,
   שסובלת הרבה יותר טוב מרעש בפורמט (שבירת עמוד באמצע תיאור, רווחים
   לא אחידים וכו'). כאן, החילוץ מבוסס על זיהוי טבלאות + ביטויים
   רגולריים לפי התיאור המילולי של הפורמט בסקיל — **בלי שראיתי קובץ
   אמיתי אחד**. יש לי רשת ביטחון אמיתית שאסור לוותר עליה: לכל חשבונית
   נבדק שסכום השורות שחולצו שווה בדיוק ל-Grand Total המוצהר בקובץ, וגם
   הסכום הכולל אחרי האיחוד נבדק מול סכום כל ה-Grand Total-ים. אם החילוץ
   שגוי — הכלי **יעצור עם שגיאה ברורה** ולא ישלח החוצה חשבונית שגויה.
   אבל זה לא ערובה מוחלטת (תיאורטית אפשר "לפגוע" בסכום הנכון עם שיוך
   שורות שגוי) — לכן: **בהרצה הראשונה עם קבצים אמיתיים, בדקו ידנית שורה
   מול שורה בין ה-Excel שיוצא לבין ה-PDF-ים המקוריים.** אם זה תואם —
   אפשר לסמוך על זה קדימה. אם לא — שלחו לי דוגמה (אפשר עם נתונים
   מוסתרים) ואכייל את הביטויים הרגולריים בקובץ `logic/kbb_invoice.py`
   (יש שם הערה בראש הקובץ שמסמנת בדיוק את המקום).

**דעתי המקצועית:** לכלי ה-SMS ולכלי ה-Packing List אני בטוח ברמה גבוהה —
תבדקו אותם ותראו שהם עובדים. לכלי החשבונית אני ממליץ להריץ אותו במקביל
לתהליך הידני (או מול Claude כרגיל) על כמה משלוחים אמיתיים לפני שמפסיקים
לבדוק, פשוט כי מדובר במסמך שיוצא ללקוח/למכס וטעות שם עולה כסף.

## מבנה הפרויקט

```
app.py                  # שרת Flask, כל ה-routes
logic/
  weekly_sms.py          # תהליך ה-SMS השבועי
  kbb_packing_list.py    # איחוד תעודות משלוח
  kbb_invoice.py         # איחוד חשבוניות (דורש תבנית אמיתית — ראו למעלה)
  office.py              # עטיפה סביב LibreOffice headless
templates/               # דפי ה-HTML
static/style.css
assets/kbb_invoice_template.xlsx   # <-- להחליף בקובץ האמיתי שלכם
tests/                   # סקריפטים שבונים קבצי דוגמה סינתטיים + לא-אמיתיים לבדיקה
uploads/ outputs/         # תיקיות עבודה זמניות (נוצרות אוטומטית, אפשר לנקות מדי פעם)
```

## מה קורה אם LibreOffice לא מותקן

הכלים יחזירו הודעת שגיאה ברורה בעברית שאומרת בדיוק את זה, במקום קריסה
סתומה. שווה לוודא לפני השימוש הראשון שהפקודה `soffice --version` עובדת
בטרמינל של המחשב שמריץ את השרת.
